## 为什么写这篇文章

在径硕网络科技（上海）有限公司担任 AI 产品实习生的 8 个月里，我深度参与了三个不同方向的 AI Agent 项目。这篇文章从 AI 解决方案工程师的视角，记录这三个项目的技术选型、系统架构、关键实现与交付结果。

## 项目一：药明生物官网智能获客 SDR Agent

### 业务问题

药明生物作为全球领先的生物药 CDMO 企业，海外客户咨询存在时差障碍，人工销售团队无法 7×24 小时响应，潜在客户流失率高。需要一套自动化的售前咨询系统。

### 技术方案

搭建 RAG 知识库检索系统 + 多轮对话 Agent 工作流，实现 7×24 小时自动应答。核心链路：意图识别 → 知识库检索 → 话术生成 → 人工转接兜底。

### 系统架构

- **知识库层**：企业产品文档、FAQ、案例库等内容进行分块与向量化处理，存储到向量数据库
- **检索层**：基于用户意图进行语义检索，返回相关文档片段
- **生成层**：LLM 基于检索结果 + Prompt 模板生成回复话术
- **兜底层**：无法处理的高价值咨询自动转接人工销售

### 关键实现

- 设计文档分块策略，平衡检索精度与上下文完整性
- 开发多轮 Prompt 模板，优化回复准确性与语气一致性
- 实现知识库增量更新机制，支持产品资料变更后快速刷新

### 交付结果

Agent 上线后覆盖售前咨询全流程，通过交互数据分析持续优化检索策略与 Prompt 模板。

## 项目二：OpenClaw 企业内部 AI 效率工具

### 业务问题

企业内部员工获取开发数据需切换数据库、Git、K8s 等多个系统，效率低下且缺乏统一入口。需要一个统一的信息获取工具。

### 技术方案

基于 OpenClaw 平台开发企业微信 AI Agent，将自然语言转化为结构化查询，实现统一入口。用户在企业微信中用自然语言提问，Agent 自动查询并返回结果。

### 系统架构

- **入口层**：企业微信作为统一交互入口
- **Agent 层**：OpenClaw 平台处理自然语言理解与任务编排
- **数据源接入层**：
  - 数据库：SQL 查询接口，支持开发数据查询
  - Git API：提交记录、代码统计
  - Kubernetes：Pod 状态、部署信息
- **输出层**：结构化数据返回 + LLM 自然语言总结

### 关键实现

- 开发 Git 提交统计 Agent：自动聚合开发数据生成报告
- 开发部门周报 Agent：LLM 总结 + 数据聚合，周报生成从 2 小时缩短至 5 分钟
- 实现并发请求处理与超时机制，保障系统稳定性

### 交付结果

系统上线后稳定运行，支持并发请求与超时处理，显著提升内部信息获取效率。

## 项目三：海外 inrepli 营销 Agent 平台

### 业务问题

海外 B2B 营销人员缺乏智能化工具，邮件营销、客户画像分析等环节效率不足。需要一个 AI 驱动的营销自动化平台。

### 技术方案

参与邮件营销 Agent、客户画像分析 Agent、智能推荐模块的 Agent 工作流开发。基于用户画像的 LLM 推理 → 个性化内容生成 → 多渠道触达 → 效果数据回流。

### 系统架构

- **画像层**：基于客户行为数据自动提取特征标签
- **生成层**：LLM 根据画像自动生成营销内容（邮件文案、推荐话术）
- **触达层**：多渠道推送（邮件、社交平台）
- **回流层**：效果数据回流，优化下一轮生成策略

### 关键实现

- 开发智能邮件内容生成 Agent：基于客户画像自动生成个性化文案
- 开发客户画像分析 Agent：LLM 自动提取特征标签，构建客户画像
- 协助分析交互数据，定位响应瓶颈并优化对话链路性能

### 交付结果

Agent 功能上线后协助分析交互数据，定位响应瓶颈并优化对话链路性能。

## 总结：AI 解决方案工程师的核心能力

通过这三个项目，我总结出 AI 解决方案工程师需要的三个核心能力维度：

1. **AI Agent 开发能力**：Agent 工作流开发、RAG 知识库搭建、Prompt Engineering、智能体搭建
2. **大模型应用工程能力**：LLM API 集成、向量检索、对话流程编排
3. **企业系统集成能力**：数据库查询接入、Git API 集成、Kubernetes 数据对接、企业微信应用开发

软件工程背景让我能够快速理解技术架构，将产品需求转化为可落地的技术方案——这是 AI 解决方案工程师区别于纯开发岗位的核心优势。

## 项目背景

2025 年 11 月到 2026 年 3 月，我在径硕科技担任 AI 产品实习生，参与的第一个项目是药明生物官网的 AI SDR Agent。

药明生物是全球领先的生物制药 CDMO 企业，官网流量大但访客构成复杂。当时的想法很直接：用 AI Agent 代替人工客服，7×24 小时回答访客问题，并在合适的时候引导留资，相当于一个数字化的销售开发代表（SDR）。

我负责的部分包括 Agent 的对话流程设计、知识库梳理，以及留资环节的产品逻辑。项目顺利上线，跑了一段时间之后，数据出来了。

## 一组不太好看的数据

| 指标 | 数量 |
|------|------|
| 官网访问 | 1000+ |
| 有效对话 | 300~400 |
| 销售线索 | 1 |

换算一下：

- 访问到有效对话的转化率大约是 30%~40%，这个数字其实还不错，说明 Agent 的入口设计和初始响应没有大问题
- 但访问到线索只有 0.1%，有效对话到线索也只有 0.25%~0.33%

也就是说，300 多个人跟 Agent 聊过了，最终只有 1 个人留下了联系方式。

第一眼看到这个数据的时候，直觉反应是"Agent 是不是答得不好"。但仔细想了之后，我觉得不能这么简单地下结论。

## 为什么不能直接说是 Agent 的问题

做产品最怕的就是拍脑袋归因。"线索少 = Agent 不行"，这个逻辑链太长了，中间有太多环节可能出问题。

我更倾向于这样的思路：先把现象摆出来，然后提出可验证的假设，再想办法一个个去验证。

所以这篇文章不是"我找到了答案"，而是"我观察到一个现象，并提出了几个可能的解释方向"。

## 假设一：流量意图可能才是最大的变量

药明生物的官网访客，不一定都是潜在客户。

B2B 企业的官网流量构成其实非常杂。有人来查公司基本信息，有人来看产品和服务介绍，有研究人员找技术资料，有合作伙伴来对接，也有求职者、行业同行，甚至已经是客户的人来登录后台。

真正带着采购需求来的人，可能只占很小一部分。

所以 1000 个访问不等于 1000 个销售机会。如果这 1000 个人里本来就只有一二十个人有明确的业务需求，那最终只有 1 条线索虽然仍然偏低，但至少没那么反直觉了。

公开的 2026 B2B 营销数据也能印证这一点：企业官网访客到销售线索的整体转化率通常只有几个百分点，而且流量来源、访客画像和购买意向阶段会造成巨大差异。

**正确的问题不是"1000 个人来了为什么只有 1 个留资"，而是"这 1000 个人里面到底有多少人本来就有潜在业务需求"。**

如果连分母是多少都不知道，就没法判断转化率到底是高还是低。

## 假设二：Agent 很会回答问题，但不太会识别商业意图

这是我自己觉得最值得复盘的一点。

我们当时设计 Agent 的核心任务是三件事：产品介绍、官网导航、引导留资。听起来很顺，但其实这三件事处于用户旅程的完全不同阶段。

举个例子，用户问："What services do you provide?"

Agent 回答："We provide A/B/C services…"

回答得很完整。然后呢？然后用户可能就走了。

因为"我对你们公司感兴趣"和"我现在准备采购你们的服务"，中间差了十万八千里。

Agent 不应该只判断"用户有没有问题"，还应该判断"用户有没有业务意图"。一个真正的 Lead Generation Agent，对话逻辑应该是这样的：

```
用户发起咨询
  ↓
先回答问题，建立信任
  ↓
顺势了解用户场景
  ↓
识别需求类型（信息查询 / 技术评估 / 业务采购）
  ↓
判断商业意向等级
  ↓
高意向用户进一步追问具体需求
  ↓
提供针对性的信息和方案
  ↓
自然地引导到下一步（留资 / 转接销售）
```

我们当时的 Agent 更像是一个"智能 FAQ"——你问什么我答什么，答完了顺带问一句要不要留资。但真正的 SDR 不会这么干活，SDR 会在对话中判断对方是不是目标客户，然后决定投入多少精力去推进。

## 假设三：留资的时机和价值感可能不对

假设用户问了一个具体的服务问题，Agent 回答完之后说："如果您有进一步需求，请留下您的邮箱，我们的销售团队会联系您。"

站在用户的角度想一想：**我为什么现在要给你邮箱？**

尤其是第一次访问官网的 B2B 访客，很多人还处在信息搜集（Research）阶段，远没到要跟销售对接（Evaluation）的程度。B2B 买家越来越倾向于先自己把信息摸清楚，再决定要不要和人接触。这个时候过早地要求留资，反而会把人吓跑。

更好的做法应该是先给够价值，再提出下一步。

比如用户问完某个服务之后，Agent 可以说：

> "根据你描述的情况，我们的 XX 服务可能比较匹配。如果你愿意，我可以先帮你整理一份针对你们这类场景的方案概述，不需要销售介入。"

等用户觉得有价值了，再顺势说：

> "如果后续希望我们的技术团队进一步评估可行性，可以留下你的工作邮箱，我会把资料和评估邀请一起发过去。"

这个时候留资的心理成本就低多了——用户不是在"给销售留个联系方式等被骚扰"，而是在"换取一份有针对性的资料"。

## 假设四：不同意向的用户应该走不同的路径

这是一个产品设计层面的问题。

三个用户问了三个不同的问题：

| 用户 | 问题 | 意向等级 |
|------|------|----------|
| A | "What does WuXi Biologics do?" | 低 |
| B | "Do you provide cell line development services?" | 中 |
| C | "We're looking for a CMO for our phase 2 program. How can we discuss this with your team?" | 高 |

如果这三个用户走的是完全一样的对话流程，面对的是同一个留资 CTA，那就浪费了 Agent 的价值。

低意向的用户，你别追着要联系方式，好好回答问题，让他对品牌留下好印象就行了。中意向的用户，可以多了解一下他的具体场景，推荐相关服务，软性地推一下资料下载或者白皮书。高意向的用户，别绕弯子，快速确认需求，收集关键字段，直接转销售跟进。

这种分层处理说起来简单，但要做好需要在 Agent 的系统设计里就把意图识别和分流逻辑做进去，而不是所有用户共用一套话术。

## 假设五：我们缺少完整的漏斗数据

这是最遗憾的一点，也是我觉得最值得在面试里拿出来讲的一点。

我们手里只有三个数字：访问量、有效对话数、线索数。中间发生了什么，全是黑箱。

如果当时我们做了更细的埋点，比如：

| 阶段 | 人数 |
|------|------|
| 网站访问 | 1200 |
| 点击启动 Agent | 450 |
| 产生有效对话（≥2 轮） | 380 |
| 咨询具体产品/服务 | 250 |
| 表达明确业务需求 | 60 |
| 表现出高购买意向 | 15 |
| 点击留资按钮 | 5 |
| 完成留资表单 | 1 |

那问题出在哪一步，一目了然。

如果 380 个有效对话里只有 60 个问到了具体产品，那可能是流量质量问题，或者 Agent 没有主动引导话题。如果 60 个有需求的人里只有 15 个表现出高意向，那可能是 Agent 的意向识别和需求挖掘做得不够。如果 15 个高意向的人里只有 5 个点了留资按钮，那是留资的时机和价值感有问题。如果 5 个点了按钮的人里只有 1 个填完了表单，那才是表单本身或者 CTA 的问题。

没有这个漏斗，所有的归因都只是猜测。

## 写在最后

项目结束的时候，我给自己的总结是这样一句话：

> Agent 的问题可能不是"不会聊天"，而是"没有把聊天转化成业务意图"。

我们花了很多精力让 Agent 回答得准确、礼貌、有品牌感，但在"识别用户处于什么阶段"和"把对话往业务方向推进"这两件事上，做得远远不够。

当然，上面说的这些都是假设。真实情况可能是其中某一个因素主导，也可能是好几个因素叠加。要验证这些假设，需要更完整的数据，也需要下一轮的迭代。

但这正是做产品有意思的地方——你看到一个现象，提出几个可能的解释，然后想办法去验证，再根据验证结果调整方向。

比"找到答案"更重要的，是**用正确的方式去找答案**。

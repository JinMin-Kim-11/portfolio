## 一句话结论

> Agent 的问题可能不是"不会聊天"，而是"没有把聊天转化成业务意图"。

这篇文章不是项目介绍，而是一次完整的产品复盘。

## 真实数据

药明生物官网 SDR Agent 上线后，跑出的数据是：

| 指标 | 数量 |
|------|------|
| 官网访问 | 1000+ |
| 有效对话 | 300~400 |
| 销售线索 | 1 |

换算成转化率：

- 访问 → 有效对话：约 30%~40%
- 访问 → 线索：约 0.1%
- 有效对话 → 线索：约 0.25%~0.33%

真正异常的是后半段——300 多次有效对话，最终只有 1 条线索。

## 我不会直接下结论

如果只根据这些数据就说"Agent 做得不好，所以转化率低"，这是不专业的。

真正成熟的产品思维是：

**现象 → 数据 → 假设 → 验证 → 迭代**

而不是"我觉得就是这个原因"。

我把原因分成"已经可以确认的"和"目前只能推测的"两层，提出了 5 个可验证的假设。

## 假设一：最大的问题可能不是 Agent，而是流量意图

药明生物是 B2B 企业，官网访问者不一定是潜在客户。可能只是：

- 查公司信息
- 查产品/服务
- 研究人员了解资料
- 合作伙伴
- 行业人员
- 求职者
- 已有客户
- 真正寻找供应商的人

1000 个访问 ≠ 1000 个销售机会。

B2B 网站大量访客处于信息搜集阶段，而不是采购阶段。公开的 2026 B2B 数据显示，整体网站访客到 lead 的转化通常只有几个百分点，而且流量来源和购买意向会造成很大差异。

所以正确的问题不是"1000 个人来了，为什么只有 1 个人买"，而是：

**这 1000 个人里面，到底有多少人本来就有潜在业务需求？**

## 假设二：Agent 回答问题很强，但识别销售意向不够强

我当时设计的 Agent 核心任务是：产品介绍 + 官网导航 + 留资。

但这三件事处于完全不同的阶段。

用户问："What services do you provide?"

Agent 回答："We provide A/B/C services..."

回答完成了。但用户可能就走了。

因为"我对你们公司感兴趣"不等于"我现在准备采购你们的服务"。

Agent 不能只判断用户有没有问题，还应该判断用户有没有业务意图。正确的设计应该是：

`
用户咨询
  ↓
了解用户场景
  ↓
识别需求类型
  ↓
判断商业意向
  ↓
高意向用户进一步追问
  ↓
提供针对性信息
  ↓
自然引导留资
`

这才是真正的 Lead Generation Agent。

## 假设三：留资对于用户来说缺少足够价值

假设用户问："你们有没有 XX 服务？"

Agent 回答完，接着说："如果您有进一步需求，请留下您的邮箱。"

用户会想：**我为什么现在要给你邮箱？**

尤其是第一次访问官网的陌生 B2B 用户，可能只是处于 Research 阶段，而不是 Evaluation / Purchase 阶段。

B2B 买家越来越倾向于先自行获取信息，再决定是否和销售接触。过早要求人工联系或提交信息，本身可能成为转化阻力。

更好的设计是：先给价值 → 理解需求 → 再提出下一步。

例如：

> "根据你描述的情况，我们的 XX 服务可能比较匹配。如果你愿意，我可以帮你整理一个针对你们场景的解决方案。"

然后再说：

> "如果希望我们的团队进一步评估，可以留下工作邮箱。"

这个时候留资的心理成本会低很多。

## 假设四：Agent 没有把高意向用户单独处理

这是一个关键的分层设计问题。

| 用户 | 话语 | 意向等级 |
|------|------|----------|
| 用户 A | "What does WuXi Biologics do?" | 低 |
| 用户 B | "Do you provide X service?" | 中 |
| 用户 C | "We are looking for X service for our clinical program. How can we discuss this with your team?" | 高 |

如果三个用户全部进入同一套聊天 → 同一个留资 CTA，那就浪费了 Agent 的价值。

应该做的分层：

- **低意向** → 信息回答 → 不强制留资
- **中意向** → 深入了解需求 → 推荐相关服务 → 软性留资
- **高意向** → 快速确认需求 → 收集关键字段 → 直接 Lead → 销售跟进

## 假设五：我们缺少漏斗数据

这是最值得在面试里讲出来的部分。

我知道的数据：1000+ 访问、300~400 有效对话、1 条线索。

但我不知道的：300~400 个人到底为什么没留资？

如果我们有这些数据：

| 阶段 | 人数 |
|------|------|
| 网站访问 | 1200 |
| Agent 启动 | 450 |
| 有效对话 | 380 |
| 产品咨询 | 250 |
| 明确需求 | 60 |
| 高意向 | 15 |
| 点击留资 | 5 |
| 完成留资 | 1 |

那马上就知道问题在哪：

- 380 → 60 掉得厉害 → 需求识别 / 流量质量有问题
- 60 → 15 掉得厉害 → Agent 没有很好识别和培养意向
- 15 → 5 掉得厉害 → 留资机制有问题
- 5 → 1 掉得厉害 → 表单、CTA、留资流程有问题

没有这个漏斗，所有归因都只是猜测。

## 最终判断

我不会写："药明生物 Agent 转化率低，因为 Agent 做得不好。"

我会写：

> "项目上线后，Agent 获得了一定真实用户互动，但最终销售线索产出有限。复盘后发现，问题不能简单归因于 Agent 本身，而需要从流量意图、用户咨询阶段、Agent 意图识别、留资时机以及销售漏斗数据几个层面共同分析。"

而且我现在不能证明"为什么只有 1 条线索"，因为手里的数据还不够。

我只能说：**我观察到了低转化现象，并提出了几个可验证的假设。**

这反而是非常好的产品思维。

## 这篇文章的核心观点

Agent 的问题可能不是"不会聊天"，而是"没有把聊天转化成业务意图"。

真正需要解决的不是对话能力，而是：

1. 识别用户处于哪个阶段
2. 判断用户有没有商业意向
3. 根据意向等级做不同的事
4. 在对的时机提出留资

如果这篇文章按照这个逻辑写，比写一个"药明生物 Agent 项目介绍"强很多。

## 同一个项目，面试官想看的东西不同

药明生物官网智能获客 SDR Agent 是我实习期间深度参与的项目。当我把这个项目写进作品集时，面对产品经理和解决方案工程师两个方向，我需要讲两个不同的故事。

## 产品经理视角：用户需求 → 产品方案 → Agent 流程 → 数据反馈

在产品经理版本中，我的重点是：

- **业务问题**：海外客户咨询存在时差障碍，人工销售团队无法 7×24 小时响应，潜在客户流失率高
- **产品方案**：设计 AI 销售助手产品方案，覆盖售前咨询全流程，从意图识别到人工转接形成完整闭环
- **用户旅程**：梳理海外客户咨询旅程，识别关键触点与痛点，输出需求分析文档与用户场景地图
- **Agent 流程**：设计对话工作流——意图识别 → 知识库检索 → 话术生成 → 人工转接，定义每个环节的产品规则
- **数据反馈**：上线后建立转化漏斗追踪机制，分析用户交互数据，持续迭代优化对话流程与知识库内容

每一项都在回答：**做什么？为什么做？用户价值在哪里？**

## 解决方案工程师视角：业务问题 → 技术方案 → 系统架构 → 交付结果

在解决方案工程师版本中，同一个项目变成了：

- **业务问题**：海外客户咨询存在时差障碍，人工销售无法 7×24 小时响应，潜在客户流失
- **技术方案**：搭建 RAG 知识库检索系统 + 多轮对话 Agent 工作流，实现 7×24 小时自动应答
- **系统架构**：知识库（文档分块+向量化）→ 意图识别 → 检索增强生成 → 话术输出 → 人工转接兜底
- **关键实现**：设计文档分块与向量化策略，开发多轮 Prompt 模板优化回复准确性与语气一致性，实现知识库增量更新机制
- **交付结果**：Agent 上线后覆盖售前咨询全流程，通过交互数据分析持续优化检索策略与 Prompt 模板

每一项都在回答：**怎么落地？架构是什么？交付了什么？**

## 最大的区别：展示重点完全不同

| 维度 | 产品经理视角 | 解决方案工程师视角 |
|------|------------|----------------|
| 核心问题 | 做什么 | 怎么落地 |
| 重点 | 用户/业务 | 技术/系统 |
| 药明生物 | 用户需求、留资场景、产品方案 | Agent Workflow、Knowledge Base、Prompt |
| OpenClaw | 内部用户、信息获取痛点、产品设计 | 数据库/Git/K8s/企微集成 |
| Inrepli | 用户反馈、产品迭代 | Agent Workflow、测试验收 |

## 解决方案页面最容易犯的错：变成技术简历

这是我最担心的。如果进入解决方案页面后，看到的是：

> Python / FastGPT / RAG / Prompt / MySQL / Git / K8s / Docker / React / TypeScript

然后一大堆技术 Logo。

不要这样。

因为你真正有竞争力的不是"我会多少技术"，而是"我能把这些东西组合起来解决业务问题"。

所以解决方案页面一定要按照 Business Problem → Solution → Architecture → Implementation → Result 来展示。这比技术栈重要得多。

## 双入口的真正价值

不是简单地：产品经理页面复制一份，解决方案页面复制一份。

而是：同一个项目，两种思维方式重新解释。

这会让面试官觉得你真的理解产品和技术之间的区别。
